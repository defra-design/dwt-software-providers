Jira ticket DWTSPI-486

Add a cookie banner for Google Analytics

Clickable prototype: v2: Cookies for Google Analytics, option D. This is also the design reference.

User story

As a software provider reading the developer guide,
I want to choose whether analytics cookies are used,
so that the guide only measures my use of it if I agree.

Context

The guide needs to ask for consent before using Google Analytics. This is option D, based on the Material for MkDocs cookie message. The tech lead confirmed that, with only one optional cookie, the message can be buttons only. This also removes the checkbox, which fails colour contrast.

Components and patterns

  • Cookie message: the built-in Material for MkDocs custom cookies feature, with its wording changed. No new components. Related guidance: Cookie banner. This option does not follow that pattern fully (see out of scope).

Design specification

Cookie message

  1. D1. The message is shown on a user’s first visit, as a pop-up with no dark overlay, so the page behind stays visible.
  2. D2. The title is “Cookies for Digital waste tracking developer guide”.
  3. D3. The text is “We use analytics cookies so we can understand how you use the service and make improvements.”
  4. D4. Below that is “We use these cookies to measure:” followed by a bulleted list:
    • how you got to this site
    • the pages you visit and how long you spend on each page
    • what you click on while you’re visiting this site
  5. D5. The only controls are the buttons “Accept analytics cookies” and “Reject analytics cookies”. There is no “View cookies” button, checkbox or label.
  6. D6. Selecting either button saves the choice and hides the message. Analytics stays off until the user accepts.

Footer

  1. D7. The footer has a link “Change your cookie settings”, which reopens the message on any page.
  2. D8. The pages match the design reference.

Acceptance criteria

  1. Given a user has not made a choice, when they open any page, then the cookie message is shown.
  2. Given the message is shown, when the user selects “Accept analytics cookies”, then the message is hidden and analytics cookies are allowed.
  3. Given the message is shown, when the user selects “Reject analytics cookies”, then the message is hidden and analytics cookies are not set.
  4. Given a user has made a choice, when they open another page, then the message is not shown.
  5. Given a user has made a choice, when they select “Change your cookie settings” in the footer, then the message is shown again.
  6. Given a user has not accepted, then no Google Analytics cookies are set.

Accessibility acceptance criteria

  1. The buttons and the text meet the minimum colour contrast of 4.5:1 for text and 3:1 for button boundaries (1.4.3, 1.4.11).
  2. The list of what the cookies measure is a real list (1.3.1).
  3. Every function works with a keyboard, in a logical order, with a visible focus state (2.1.1, 2.4.3, 2.4.7).
  4. The footer link text describes what it does, and the buttons’ names say what they do (2.4.4, 4.1.2).
  5. There is no horizontal scrolling at 320px wide or at 200% zoom (1.4.4, 1.4.10).

How to test

  • Run an automated check (axe or WAVE).
  • Use the message and the footer link with a keyboard only.
  • Use a screen reader (NVDA or VoiceOver) to check the message and buttons.
  • Check at 320px wide and at 200% zoom.

Accessibility statement

Failed: 2.4.11 Focus Not Obscured (Minimum), level AA. With the page scrolled to the bottom, the pop-up covers the footer links, including “Change your cookie settings” and “Accessibility Statement”, and the lower part of the left-hand navigation. The page cannot scroll further.

A keyboard user tabbing through the footer cannot see the focused link, and cannot dismiss the message without moving focus past those links.

Out of scope

The team is accepting these usability shortfalls because it is moving to GOV.UK Frontend soon and will put the effort there.

  • The message does not appear without JavaScript, so those users never see it and analytics stays off.
  • When the message is reopened, it does not show the user’s earlier choice.
  • Accept and reject have equal visual weight, which does not follow the GOV.UK cookie banner pattern.
  • There is no confirmation message after a choice and no separate cookies page.
  • The message has no close (x) button, so that state is not designed.
  • Fixing the accessibility failure above (2.4.11): the message covers the footer and the focused link, and is last in the tab order.
  • The prototype saves the choice in the browser only. It does not switch real analytics on or off.
  • Cookie names and expiry times have not been confirmed.
