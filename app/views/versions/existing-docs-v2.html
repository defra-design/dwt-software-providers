Changes and design rationale

Context

The site needs to ask for consent before using Google Analytics. Material for MkDocs has a built-in custom cookies feature, so this version mocks what it produces rather than a bespoke design.

Option A: Material for MkDocs cookie message

What the built-in feature produces, with no customisation.

  • Cookie message shown on first visit, with Accept, Reject and Manage settings buttons.
  • Manage settings reveals a Google Analytics checkbox, ticked by default. Accept then saves the choice shown.
  • “Change cookie settings” link in the footer reopens the message on any page.

Differences from the GOV.UK cookie banner pattern:

  • It is a modal over the page. The GOV.UK pattern is a non-blocking banner.
  • There is no confirmation message after a choice is made.
  • There is no cookies page listing each cookie.
  • The checkbox is ticked by default, so cookies are on unless the user unticks it.
  • With settings open, the button still says “Accept”, which may be unclear when the user has unticked the box.
  • Without JavaScript the message does not show, so users cannot change settings.

Option B: GOV.UK cookie banner pattern

Material customised towards the GOV.UK cookie banner component. It would need a template override and extra CSS and JavaScript in the MkDocs project.

  • Non-blocking banner above the header, after the skip link, with “Accept analytics cookies”, “Reject analytics cookies” and a “View cookies” link.
  • Confirmation message after a choice, with a link to change settings and a “Hide cookie message” button.
  • “Manage settings” is replaced by “View cookies”, which goes to a cookies page. The page explains the cookies and has Yes and No radios with “Save cookie settings”. The default is No, and saving shows a success message.
  • “Cookies” link in the footer goes to the cookies page. The banner is not shown on that page.
  • The banner does not show without JavaScript. The cookies page tells users they need JavaScript to change settings.
  • Banner and cookies page use GOV.UK Frontend components compiled into a separate stylesheet, so Material’s styles are untouched.

The banner and cookies page are draft copy, not agreed wording. Cookie names and expiry times (_ga and _ga_<container-id>, 2 years) are the standard Google Analytics 4 values and need checking against the real configuration.

Option C: Material for MkDocs cookie message with GOV.UK-style wording

The same Material component as option A, with content supplied by the team. It needs no template override.

  • Title: “Cookies for Digital waste tracking developer guide”.
  • Description: “We use some essential cookies to make this service work.” and “We’d also like to use analytics cookies so we can understand how you use the service and make improvements.”
  • Buttons: “Accept analytics cookies” and “Reject analytics cookies”.
  • “View cookies” replaces “Manage settings”. It reveals the Google Analytics checkbox in the message, rather than going to a cookies page.

Still different from the GOV.UK pattern: it is a modal, has no confirmation message or cookies page, and the checkbox is ticked by default. “View cookies” does not take the user to a page, which may not match what the label suggests. The “Accept analytics cookies” button also saves the checkbox state, so it may be unclear if the user has unticked the box. The text does not say how to change settings later, though the footer link still does this.

Option D: Material for MkDocs cookie message, analytics only

Based on option A. The tech lead confirmed that, with only one optional cookie, the message can be buttons only. This also removes the checkbox, which fails colour contrast.

  • Title: “Cookies for Digital waste tracking developer guide”.
  • Text: “We use analytics cookies so we can understand how you use the service and make improvements.” then “We use these cookies to measure:” and a list of what they measure: how you got to the site, the pages you visit and how long you spend on each, and what you click on.
  • Buttons: “Accept analytics cookies” and “Reject analytics cookies”. There is no “View cookies” button, checkbox or label.
  • Selecting either button saves the choice and hides the message. Analytics stays off until the user accepts.
  • The footer link “Change your cookie settings” reopens the message.
  • A pop-up, not a modal: there is no dark overlay, so the page behind stays visible.

The Material message has no close (x) button, so that state has not been mocked. The supplied text said “this sites”, which is corrected to “this site”. In this prototype the choice is saved in the browser but no analytics are switched on or off.

Questions

  • Is Google Analytics the only optional cookie, or are others needed?
  • Who owns the cookie wording and the cookies page?
  • Can the MkDocs project take a template override, extra CSS and JavaScript for option B?
  • Does the guide set any other cookies that need listing on the cookies page?
