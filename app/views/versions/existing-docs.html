Changes and design rationale

Context

The API specification page has a “Recent and upcoming changes” section. These are draft recommendations on how to write and manage future change notifications. They need sense checking against the current API update process.

Changes

  • New “Upcoming changes” page in the API tab and left-hand navigation.
  • Removed “Recent and upcoming changes” from the API specification page, which now links to the new page.
  • Each change is one entry with a type, status, a date for each environment, who it affects and what the user needs to do.
  • Lifecycle: planned, then in the external test environment, then in production. When a change reaches production it moves, with the same title and text, to the change log. Users see it in one place at a time.

Questions

  • Does the change log only show changes once they are in production, or also for updates to the external test environment?
  • Can notifications be moved into the change log as they enter production?
  • Can software providers subscribe to updates? They are unlikely to remember to check the page.

Comments

  • The change log is not in date order. For example, the 21 October 2026 change is at the bottom.
  • The change log is hard to navigate and we need to understand how it works.
